# Часовой пояс и лимиты трафика

[← README](../README.md)

## Часовой Пояс

Показать текущий часовой пояс менеджера:

```bash
xray-client timezone
```

Изменить часовой пояс:

```bash
xray-client set-timezone Europe/Moscow
```

Вернуться к системному времени сервера:

```bash
xray-client set-timezone server
```

Эта настройка сохраняется в `/usr/local/etc/xray/server.env` как `MANAGER_TIMEZONE`.
Она влияет на сроки доступа клиентов, дневные и месячные лимиты трафика, отчёты по дням/часам и отображение времени в таблицах.

Пустое `MANAGER_TIMEZONE` использует настоящую локальную зону сервера: сначала файл `/etc/localtime` через `ZoneInfo.from_file`, затем IANA-зону из `TZ`, если файл отсутствует, недоступен или повреждён. Если оба источника недоступны или неверны, применяется фиксированное текущее смещение системы. При доступной зоне переходы на летнее время учитываются для даты события: например, `Europe/Berlin` даёт зимой `+01:00` / `CET`, летом `+02:00` / `CEST`.

Неверное значение настройки также переключает расчёты на локальную зону сервера. Шапка меню, `xray-client timezone`, подписи отчётов Telegram и активности показывают общую пометку:

```text
MANAGER_TIMEZONE invalid: Mars/Base (server local time)
```

Меню продолжает работать, а отчёты и интервалы трафика используют локальный календарь. `xray-test` сохраняет `FAIL` проверки `Manager timezone` с той же пометкой; остальные проверки времени получают локальную зону без исключения. Просмотр настройки и отчётов не исправляет `server.env` и не переписывает сроки доступа. Для исправления используйте `xray-client set-timezone Europe/Moscow` или `xray-client set-timezone server`: новое неизвестное имя по-прежнему отклоняется до изменения состояния. Сохранённые моменты UTC не меняются.

Псевдонимы `server`, `local`, `system` и другие локальные варианты используйте как аргумент `set-timezone`: команда сохраняет пустое значение. Если псевдоним записан прямо в `server.env`, чтение использует локальную зону, но `xray-test` выдаёт `FAIL`: таймер ротации raw-логов получает это имя в `OnCalendar`. Исправление — `xray-client set-timezone server`.

Хвостовой комментарий после пробела или табуляции вне кавычек не входит в имя зоны: `MANAGER_TIMEZONE=Europe/Moscow # основная зона` задаёт валидную `Europe/Moscow` (см. [Формат server.env](backups-and-data.md#формат-serverenv)). После смены зоны команда `set-timezone` пересобирает таймер ротации raw-логов. Для применения новой зоны к ежедневной проверке срока доступа отдельно выполни `xray-vps-manager units sync --check`, проверь список отличий и запусти `xray-vps-manager units sync`. Полный sync применяет все найденные отличия управляемых unit-файлов.

При смене часового пояса существующие даты окончания доступа нормализуются к `00:00` выбранной зоны с сохранением календарной даты: срок «до 5 октября» остаётся «до 5 октября» при переходе и на восток, и на запад, меняется только момент отключения — теперь это полночь новой зоны. Календарная дата берётся из сохранённого срока как записана, без пересчёта момента в новую зону.

После нормализации команда печатает строки `WARN:` по отдельным клиентам:

```text
WARN: client ИМЯ: access date changed 2026-10-20 -> 2026-10-19
WARN: client ИМЯ: access until 2026-10-17 00:00 has already passed in the new timezone, access is expired
WARN: client ИМЯ: disabled as expired, but access until 2026-10-05 00:00 has not passed yet in the new timezone; enable it: xray-client enable ИМЯ
```

- Первая строка значит, что дата в `xray-client list` до смены отличалась от новой. Так бывает только у нестандартного значения срока в `manager.db` (без смещения или в UTC, например после ручной правки); проверьте срок и при необходимости задайте его заново через `xray-client set-days`.
- Вторая строка значит, что срок был в будущем, а полночь его даты в новой зоне уже прошла — например, при смене зоны на восток в последний день доступа. Клиент считается истёкшим, и минутная проверка `expire-due` его отключит; если это не нужно, продлите доступ через `xray-client extend-days`.
- Третья строка — обратный случай при смене зоны на запад: срок уже истёк и `expire-due` отключил клиента, а в новой зоне полночь его даты ещё не наступила. Автоматически такой клиент не включается; включите его командой из подсказки, иначе он останется отключённым до конца срока.

Эта же команда пересобирает systemd timer ротации raw Xray logs: `xray-raw-log-rotate.timer` получает точный `OnCalendar` из `MANAGER_TIMEZONE` и `XRAY_RAW_LOG_ROTATE_TIME`, поэтому после перезапуска сервера systemd продолжает запускать ротацию в выбранной зоне, а не по времени сервера.

В меню `Сервис и диагностика` -> `Изменить часовой пояс` значение выбирается из списка. Там же есть поиск по полному IANA-списку, чтобы не вводить timezone вручную.


## Лимиты Трафика

Лимит задаётся в гигабайтах и считается по общему трафику клиента:

```text
TOTAL = IN + OUT
```

По умолчанию лимит не установлен. Если дневной лимит исчерпан, клиент отключается до следующего календарного дня. Если месячный лимит исчерпан, клиент отключается до следующего календарного месяца. После смены периода менеджер автоматически включает клиента обратно, если текущий расход нового дня или месяца ниже лимита и срок доступа клиента не истёк.

Показать лимиты и текущий расход:

```bash
xray-client limit-list
```

Установить дневной лимит 15 GB:

```bash
xray-client set-limit ИМЯ daily 15
```

Установить месячный лимит 150 GB:

```bash
xray-client set-limit ИМЯ monthly 150
```

Убрать лимит:

```bash
xray-client clear-limit ИМЯ
```

Проверить лимиты вручную:

```bash
xray-client enforce-limits --sync
```

Автоматическая проверка выполняется раз в минуту после сохранения статистики `xray-traffic-sync.timer`: она отключает клиентов при превышении и возвращает доступ после сброса дневного или месячного периода, если срок доступа клиента не истёк.

## Суммарная Сводка Трафика

В меню `Трафик и активность` -> `Просмотр трафика` перед выбором клиента показывается короткая сводка за текущий месяц:

```text
TOTAL      общий трафик всех клиентов за месяц
TOTAL x2   оценка расхода VPS-провайдера с включённым множителем x2
```

Строка `TOTAL x2` выключена по умолчанию. Её можно включить, отключить или изменить множитель через `Трафик и активность` -> `Настройки` -> `Настройки суммарного трафика`. В `Просмотр трафика` также есть быстрый вход `S Настройки TOTAL`. Настройки хранятся в `/usr/local/etc/xray/server.env` как `TRAFFIC_TOTAL_MULTIPLIER_ENABLED` и `TRAFFIC_TOTAL_MULTIPLIER`.

Множитель полезен для VPS-провайдеров, которые считают входящий и исходящий трафик в общий лимит. Для VPN-сценария эти направления часто близки по объёму, поэтому `TOTAL x2` помогает быстро оценить расход месячного лимита сервера.

## Отчёты По Трафику

`xray-traffic-sync` хранит постоянные cumulative-счётчики клиента и rolling history по часам/дням за 6 месяцев. Если клиент создан внутри retention-окна, sync сверяет сумму сохранённой history с cumulative-счётчиками и дозаполняет недостающую разницу, чтобы месячные и периодные отчёты не отставали от `ALL TIME`.

Показать сводку по клиентам за текущий месяц:

```bash
xray-client traffic-summary
```

Показать сводку по клиентам за конкретный месяц:

```bash
xray-client traffic-summary 2026-06
```

Показать трафик клиента за день по часам:

```bash
xray-client traffic-day ИМЯ 2026-06-04
```

Показать трафик клиента за 7 дней по дням, начиная с указанной даты:

```bash
xray-client traffic-week ИМЯ 2026-06-01
```

Показать трафик клиента за месяц по дням:

```bash
xray-client traffic-month ИМЯ 2026-06
```

Показать трафик клиента за произвольный период по дням:

```bash
xray-client traffic-period ИМЯ 2026-06-01 2026-06-30
```

Если у клиента несколько credentials, команды `traffic-day`, `traffic-week`, `traffic-month` и `traffic-period` после общей таблицы дополнительно выводят блок `Credentials`. В нём видно разрез за выбранный период по каждому protocol credential: `PROTOCOL`, `SECURITY`, `TRANSPORT`, `CONNECTION`, `STATUS`, `IN`, `OUT` и `TOTAL`. Это помогает отличить расход VLESS, Trojan и других подключений одного клиента.

Проверить и отключить клиентов с истёкшим сроком вручную:

```bash
xray-client expire-due
```

`xray-traffic-sync.timer` выполняет эту проверку каждую минуту вместе со сбором статистики, поэтому отключение срабатывает по часовому поясу менеджера. `xray-client-expire.timer` остаётся дополнительной ежедневной проверкой.
