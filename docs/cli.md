# CLI: справка, аргументы и ошибки

[← README](../README.md)

Команды `xray-*` и `xray-vps-manager COMMAND` используют общую границу CLI. Например, `xray-client list` соответствует `xray-vps-manager client list`. Алиасы общей команды: `set-bypass` → `bypass`, `set-cascade` → `cascade`, `traffic` и `sync` → `traffic-sync`.

## Справка и аргументы

Отдельный аргумент `-h`, `--help` или `help` показывает справку в stdout и возвращает код 0. Справка доступна без root, конфигурации и базы; она не запускает рабочее действие. Например:

```bash
xray-menu --help
xray-client help
xray-vps-manager activity --help
```

Неизвестные команды и флаги, лишние или недостающие аргументы, повторные и несовместимые флаги возвращают код 2: `ERROR: …` и короткую строку `Usage:` в stderr. Проверка формы аргументов выполняется до root и доступа к состоянию. Сочетание `--help --unknown` считается ошибкой. Значения имени, срока, порта и других параметров по-прежнему проверяет соответствующая операция; её ошибка обычно возвращает код 1.

Токены с префиксом `--` распознаются как опции. Точный `-h` зарезервирован для справки: отдельно он показывает help, среди других позиционных аргументов возвращает код 2. Остальной текст с одиночным дефисом, например `-ddos source`, `-` или `-3`, передаётся обработчику как позиционное значение.

Запуск без аргументов:

| Команда | Действие |
| --- | --- |
| `xray-vps-manager`, `xray-client`, `xray-backup`, `xray-update`, `xray-manager-update` | Справка, код 0 |
| `xray-vps-manager sqlite`, `xray-vps-manager units` | Справка, код 0 |
| `xray-menu` | Интерактивное меню |
| `xray-activity`, `xray-telegram`, `xray-warp` | Статус |
| `xray-traffic-sync` | Синхронизация; поддерживается только рабочий флаг `--quiet` |
| `xray-set-cascade`, `xray-set-bypass` | Добавление с вводом необходимых данных |
| `xray-test` | Диагностика |

## Права root

Рабочие действия меню, клиентов, активности, Telegram, трафика, backup, Xray update, cascade, bypass и WARP требуют root. Если SSH-сеанс уже открыт под root, порядок работы меню сохраняется. При запуске от обычного пользователя команда завершится с кодом 1 и сообщением `ERROR: Run this script as root.`.

У `xray-manager-update` root требуется для обновления и отката; `--check` и `--backups` доступны без этой проверки. Команды `sqlite` и `units` не имеют общей проверки UID, но доступ к файлам и systemd определяется правами ОС. `xray-test` сообщает о недостаточных правах внутри диагностического отчёта.

## Ошибки и коды выхода

| Ситуация | Поток и код |
| --- | --- |
| Успех или справка | stdout, 0 |
| Ошибка формы команды | stderr: `ERROR: …` и `Usage: …`, 2 |
| Фатальная рабочая ошибка | stderr: `ERROR: …`, затем подсказка и подробности при наличии; обычно 1 |
| Прерывание Ctrl+C | 130, без traceback |
| Диагностический отчёт | stdout; прежний код результата 0 или 1 |

Специализированные ошибки сохраняют свой код выхода. Числовой `SystemExit` также сохраняется, строковый оформляется как рабочая ошибка. Проверка наличия новой версии менеджера возвращает 0 и при доступном обновлении. Строки `OK`, `WARN` и `FAIL` диагностического отчёта `xray-test` остаются в stdout.

`xray-update --backups` (алиасы `backups` и `--list-backups`) — отчёт о сохранённых версиях Xray: список выводится в stdout с кодом 0. При пустом или отсутствующем каталоге бэкапов отчёт выводит `FAIL: Нет сохранённых предыдущих версий Xray.` в stdout и возвращает 1; stderr остаётся пустым. Это отличается от невозможности выполнить `--rollback`: отсутствие бэкапа для отката — рабочая ошибка `ERROR: …` в stderr с кодом 1.

Неперехваченный `ManagerError` обрабатывается после выхода из сценария, его отката и освобождения ресурсов. Для отладки `XRAY_MANAGER_DEBUG=1` добавляет traceback такой ошибки в stderr. Другие неперехваченные исключения сохраняют traceback; существующие локальные обработчики рабочих сценариев продолжают действовать.
