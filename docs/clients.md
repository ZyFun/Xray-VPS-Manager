# Клиенты

[← README](../README.md)


Добавить клиента:

```bash
xray-client add ИМЯ
```

После команды можно ввести количество календарных дней доступа.
Пустой ввод или `0` означает бессрочный доступ.
Клиент со сроком будет автоматически отключён в `00:00` по часовому поясу менеджера после окончания срока.

Команды `xray-client`, которые меняют клиентов и подключения (`add`, `remove`, `enable`, `disable`, `set-days`, `set-limit`, `add-connection` и другие), выполняются по одной: на время чтения, изменения и записи `manager.db` и `config.json` они берут блокировку `/usr/local/etc/xray/manager.lock`. Количество дней доступа спрашивается до блокировки, поэтому ожидание ввода не задерживает другие операции. Если другая операция менеджера ещё выполняется, команда ждёт до 60 секунд, затем завершается без изменений:

```text
ERROR: Другая операция менеджера ещё выполняется: pid=PID cmd=xray-client add since=2026-10-08T10:00:00Z
Дождись её завершения и повтори команду.
```

Повтори команду, когда операция завершится. Проверки `enforce-limits` и `expire-due` ждут блокировку до 30 секунд как при ручном запуске, так и в таймере. При таймауте команда без `--quiet` завершается с ошибкой и кодом 1. С `--quiet` проверка пропускается с кодом 0 и предупреждением `WARN: … Шаг enforce-limits пропущен, следующий запуск таймера повторит его.` Для `expire-due` в предупреждении указано его имя. Остальные шаги минутного таймера выполняются, а пропущенную проверку повторит следующий запуск.

`enforce-limits --sync` сначала запускает `xray-traffic-sync --quiet`, если helper установлен, затем проверяет лимиты. Если helper отсутствует или `--sync` не указан, используется уже сохранённая статистика. При `set-limit` с ненулевым лимитом менеджер сначала сохраняет лимит, затем при наличии helper синхронизирует трафик и показывает расход. Если лимит уже превышен, сразу запускается проверка лимитов.

Команды изменения клиентов и подключений с применением `config.json` (`add`, `remove`, `enable`, `disable`, `add-connection` и другие) проверяют кандидат перед заменой рабочего конфига и созданием его технической копии. Если сериализованные байты совпадают с рабочим файлом, копия и обычный перезапуск Xray не нужны. При восстановлении прерванной реактивации `enforce-limits` может дополнительно потребовать проверяемый перезапуск даже при совпадении байтов. При изменении менеджер создаёт копию и атомарно записывает конфиг. Для операций с перезапуском он проверяет запуск Xray и локальные TCP-порты в течение 3 секунд. Если применение после записи не удалось, менеджер обычно пытается восстановить прежний конфиг. Для ограничивающего конфига при восстановлении реактивации действует исключение, описанное ниже. Для операций с перезапуском он также проверяет запуск Xray с восстановленным конфигом. Сообщение указывает причину и результат восстановления.

Для `add`, `remove`, `disable`, `enable`, `move-connection`, `set-days`, `extend-days`, `rotate-trojan-password`, `enforce-limits` и `expire-due` изменения SQLite фиксируются до применения конфига, когда оно требуется. Пишущая транзакция закрывается до применения и перезапуска Xray. При ошибке или отмене применения менеджер точечно восстанавливает затронутые данные. При необходимости также восстанавливается конфиг. При успешном откате отмена `Ctrl+C` сохраняет код 130. Если восстановление не удалось, сообщение содержит причины исходной ошибки и ошибки отката. Проверь Xray через `xray-test` и при необходимости восстанови конфиг из указанной копии вручную.

Если `expire-due` не обнаружил изменений, он не записывает клиентские данные и не перезапускает Xray. То же относится к `enforce-limits`, если нет ожидающей восстановления реактивации. При штатной остановке Xray его `ExecStop` запускает `xray-traffic-sync` с собственной пишущей транзакцией без `manager.lock`.

При возврате доступа после сброса лимита менеджер сохраняет в одной metadata-записи SQLite отпечатки отдельных credentials затронутых клиентов. Версия схемы SQLite остаётся 8. Если реактивация прервалась, следующий `enforce-limits` повторно рассматривает отмеченных клиентов с текущим сроком доступа и расходом, сверяет каждый credential и сохраняет независимые более поздние правки. Адресное отключение одного подключения сохраняется, а остальные подходящие подключения восстанавливаются, если срок и лимит это позволяют. Для восстановления локальная техническая копия конфига не нужна. Если текущий срок или лимит требуют запретить доступ, успешно установленный ограничивающий конфиг остаётся на диске даже при неподтверждённом перезапуске. Если само применение завершилось ошибкой или отменой и восстановило прежний файл, менеджер также компенсирует изменения SQLite и metadata. Следующая проверка повторяет попытку и подтверждает запуск Xray с этим конфигом.

Сценарии создания, удаления и изменения поддерживаемых подключений сначала сохраняют изменения SQLite, затем применяют Xray config, если он меняется. Переименование меняет только метаданные и не перезапускает Xray. Для изменений с управляемым Caddy site текст кандидата предварительно проверяется во временном Caddyfile отдельно от рабочего конфига. После применения Xray менеджер записывает site, проверяет полный рабочий Caddyfile, запускает или включает службу Caddy при необходимости и выполняет reload. При ошибке он пытается восстановить site, Caddyfile, состояние службы и её автозапуск, Xray config и затронутые данные SQLite. Если восстановление не удалось, состояние требует проверки. Значения для `server.env`, если они меняются, проверяются заранее и записываются последними. Ошибка записи стартовой ссылки сообщается вместе с результатом применения. Отдельная ошибка записи `server.env` может возникнуть после применения изменений.

При удалении клиентов или их ключей связанные записи активности и трафика, нужные для отката, временно сохраняются в SQLite-копию на диске в закрытом каталоге. При откате менеджер восстанавливает их порциями. При нехватке места для временной копии удаление завершается до записи изменений.

Остальные переходные клиентские операции с применением конфига сохраняют порядок «конфиг → БД». При ошибке последующей записи БД менеджер восстанавливает изменённый конфиг из копии. Для `route` данные SQLite фиксируются до применения конфига и переключения runtime-маршрута. При ошибке или отмене менеджер восстанавливает затронутые данные и исходный конфиг. Если переключение балансера могло начаться, он восстанавливает прежний override, включая его отсутствие. Если исходное состояние балансера было считано, менеджер повторно считывает override и кандидатов и сверяет их с этим состоянием. При расхождении состояние runtime остаётся неподтверждённым. Если откат не удался, сообщение содержит обе причины и указывает на неподтверждённое состояние.

Добавить клиента сразу на конкретный срок:

```bash
xray-client add ИМЯ ДНЕЙ
```

Добавить клиента в конкретное подключение:

```bash
xray-client add ИМЯ ДНЕЙ --connection TAG
```

Если на сервере ровно одно подключение нужного протокола, можно выбрать его по протоколу:

```bash
xray-client add ИМЯ ДНЕЙ --protocol trojan
```

Если подключений этого протокола несколько, команда попросит указать точный `--connection TAG`.

Тип создаваемого credential зависит от выбранного подключения. Для VLESS-подключения создаётся UUID и `vless://` ссылка. Для Trojan TLS/WebSocket-подключения через Caddy создаётся внутренний UUID менеджера, отдельный Trojan password и `trojan://` ссылка; в Xray config активный пользователь хранится в `settings.clients`.
Внутренний UUID клиента хранится отдельно от protocol credential: один клиент может иметь несколько credentials, например VLESS Reality, VLESS TLS/XHTTP и Trojan TLS/WebSocket. Для VLESS credential используется свой UUID в `vless://` ссылке, для Trojan credential - свой password в `trojan://` ссылке. Внутренний UUID клиента нужен менеджеру для SQLite, маршрутизации, Telegram-подписок и клиентского ключа `vpn-key:UUID`; он не является Trojan-паролем.
После успешного `xray-client add` команда сразу выводит ссылку подключения и `Access key: vpn-key:UUID`. Этот ключ можно передать клиенту вместе со ссылкой, чтобы он мог привязаться к Telegram-боту без protocol link.
В меню `Клиенты -> Добавить клиента` выбор подключения показывает и VLESS, и Trojan connections, поэтому клиента можно сразу добавить в нужный протокол.

Для существующего клиента используй отдельный пункт меню:

```text
Клиенты -> Добавить подключение к клиенту
```

Меню сначала показывает таблицу клиентов, затем только те VLESS/Trojan connections, которых у выбранного клиента ещё нет. Если все подключения уже добавлены, действие отменяется без изменения клиента.

Через CLI повторный вызов `xray-client add ИМЯ ... --connection TAG` добавляет существующему клиенту ещё один credential в выбранном подключении. Дублировать один и тот же `connection` для одного клиента нельзя. Срок доступа существующего клиента при этом сохраняется. Если явно передать `ДНЕЙ`, в том числе `0` или другое обозначение бессрочного доступа, команда после успешного добавления предупредит, что срок не изменён. Для его изменения используй `set-days` или `extend-days`.

Новый клиент по умолчанию бесплатный и не участвует в расчёте оплаты. Чтобы добавить платного клиента через команду:

```bash
xray-client add ИМЯ ДНЕЙ --payment paid
```

Изменить статус оплаты существующего клиента:

```bash
xray-client set-payment ИМЯ paid
xray-client set-payment ИМЯ free
```

После добавления клиента или смены статуса оплаты команда выводит текущий расчёт суммы на одного платного клиента.

Продлить срок доступа существующего клиента на N дней:

```bash
xray-client extend-days ИМЯ ДНЕЙ
```

При продлении дни прибавляются к текущей дате окончания доступа. Если срок уже истёк или не был установлен, продление считается от сегодняшней даты.

Установить срок доступа заново от сегодняшней даты:

```bash
xray-client set-days ИМЯ ДНЕЙ
```

Сделать доступ бессрочным:

```bash
xray-client set-days ИМЯ 0
```

После изменения срока менеджер сразу пересчитывает статус клиента. Если срок истёк, клиент отключается. Если срок продлён или сделан бессрочным, клиент включается обратно, но только если не исчерпан дневной или месячный лимит трафика. Лимит трафика имеет приоритет над сроком доступа.

Временно отключить клиента без удаления:

```bash
xray-client disable ИМЯ
```

Отключить только один credential клиента:

```bash
xray-client disable ИМЯ --connection TAG
```

Включить клиента обратно с той же ссылкой:

```bash
xray-client enable ИМЯ
```

Включить только один credential:

```bash
xray-client enable ИМЯ --connection TAG
```

При повторном `enable` или `disable` с `--connection TAG` сообщение об уже включённом или отключённом состоянии относится к выбранному credential. Если credential для этого подключения отсутствует, команда сообщает об этом отдельно. При `enable` сначала проверяются срок доступа и лимит трафика: если срок истёк или лимит превышен, команда сообщит об этом прежде проверки credential.

Перенести клиента в другое подключение:

```text
Клиенты -> Перенести клиента в другое подключение
```

Меню сначала попросит выбрать клиента из таблицы, затем целевое подключение. Перенос доступен клиенту с одним credential между VLESS-подключениями или между Trojan-подключениями. Если credentials несколько, добавь нужный credential отдельно.
Для включенного клиента менеджер перемещает credential между inbounds в `config.json`, проверяет Xray config, перезапускает Xray и печатает новую ссылку.
Для отключенного клиента меняется сохранённая привязка в SQLite без применения конфига и перезапуска Xray. При переносе активного клиента `xray-traffic-sync` записывает последнюю доступную дельту старого credential в общие итоги клиента. Статистика старого credential удаляется.

То же через командную строку:

```bash
xray-client move-connection ИМЯ CONNECTION_NAME_OR_TAG
```

Перенос сохраняет внутренний UUID клиента, ключ `vpn-key:UUID` и привязанную Telegram-подписку. Новая ссылка использует прежний UUID VLESS credential или пароль Trojan и параметры целевого подключения. Выдай её клиенту, поскольку порт, SNI, transport или `security` могут измениться.

Если сохранённый UUID VLESS credential расходится с данными Xray в `config.json` для включённого клиента или с сохранёнными данными Xray для отключённого клиента, перенос отклоняется до изменения данных. Сообщение указывает клиента и исходное подключение; проверь их данные перед повторной попыткой.

Полностью удалить клиента:

```bash
xray-client remove ИМЯ
```

При успешном выполнении команда удаляет клиента со всеми credentials и связанным состоянием из `config.json` и `manager.db`, включая накопленный трафик и историю. При откате удаления сначала восстанавливаются данные клиента, затем возвращается трафик, собранный при остановке Xray.

Команда не спрашивает подтверждение, поэтому её можно вызывать из скриптов. Пункт меню `Клиенты` -> `Удалить клиента` сначала показывает имя, число подключений (credentials) и трафик клиента за всё время и удаляет его только после ответа `y` на вопрос `Удалить клиента ИМЯ [y/N]`; иначе печатает `Действие отменено.`.

Повторно вывести ссылку клиента:

```bash
xray-client link ИМЯ
```

Если у клиента несколько credentials, команда выводит список ссылок по подключениям. Чтобы получить одну конкретную ссылку:

```bash
xray-client link ИМЯ --connection TAG
```

Вывести клиентский ключ для Telegram-подписки:

```bash
xray-client key ИМЯ
```

Ключ имеет вид `vpn-key:UUID` и привязан к клиенту целиком, а не к одному credential.

Проверить Trojan password policy:

```bash
xray-client trojan-password-check
```

Менеджер считает корректным Trojan password длиной 32-128 URL-safe символов. Проверка также показывает рассинхрон, если пароль активного Xray config отличается от значения в SQLite.

Сменить Trojan password для клиента:

```bash
xray-client rotate-trojan-password ИМЯ --connection TAG
```

Если у клиента только один Trojan credential, `--connection TAG` можно не указывать. Команда меняет только Trojan password выбранного credential, не меняет внутренний `vpn-key:UUID` и сразу печатает новую `trojan://` ссылку. Старую Trojan-ссылку после rotate нужно заменить у клиента.

Синхронизировать per-client cascade routing rules и balancers в `config.json`:

```bash
xray-client sync-routes
```

Клиентские правила `client-route-*` существуют, только пока общим catch-all маршрутом служит каскад. При включённом WARP или после `xray-set-cascade --disable` команда снимает их из `config.json`, а выбранные страны остаются в SQLite и вернутся вместе с каскадным маршрутом (см. [Каскад и WARP](cascade-and-warp.md#клиентские-маршруты)).

После начальной синхронизации переключить выбранную страну/каскад клиента без изменения VLESS-ссылки:

```bash
xray-client route ИМЯ
xray-client route ИМЯ Германия
xray-client route ИМЯ cascade-us
```

`route` сохраняет выбранный `cascade-*` в SQLite и через Xray API пытается переключить runtime balancer без перезапуска Xray. Если выбран тот же cascade, команда сообщает, что страна уже выбрана. Пока общим маршрутом служит не каскад (включён WARP или выполнен `xray-set-cascade --disable`), клиентских правил нет. `route` тогда ничего не меняет — ни `config.json` и SQLite, ни работающий Xray — и завершается ошибкой `Выбор страны недоступен: общий маршрут сейчас не каскад …`; выбери страну после возврата каскадного маршрута.

При смене маршрута после фиксации SQLite менеджер проверяет инварианты и временный `config.json.tmp` командой `xray run -test -format json`. Затем он считывает фактическое состояние балансера, создаёт техническую копию при изменении файла, атомарно заменяет конфиг и переключает балансер через Xray API. Действует общий предел до 20 технических копий с учётом оговорённых исключений при ошибках ротации, подробности приведены в [описании копий](backups-and-data.md#автоматические-технические-бэкапы). При восстановлении маршрута Xray также не перезапускается. Успешный откат после `Ctrl+C` сохраняет код 130.

То же действие доступно через интерактивное меню:

```text
Клиенты -> Изменить страну подключения
```

Меню сначала показывает таблицу клиентов, затем нумерованную таблицу доступных cascade-стран. После выбора меню передаёт аргументы `route ИМЯ TAG` общему CLI-адаптеру внутри процесса. Ссылка клиента не меняется; после смены страны нужно переподключить VPN, чтобы новые соединения пошли через выбранный маршрут.

Список клиентов:

```bash
xray-client list
```

В списке показываются две framed-таблицы. `Clients` агрегирует статус, оплату, страну каскада, online/offline, общий трафик, лимит, срок доступа и количество credentials клиента. `Credentials` показывает конкретные protocol credentials с protocol/security/transport/connection, отдельным online state, traffic и временем обновления traffic. Для Caddy-managed подключений `SECURITY` отображается как `tls/caddy`: публичное клиентское подключение идёт по TLS через Caddy, а локальный inbound Xray остаётся без TLS.

```text
Clients
+-------+---------+---------+---------+--------+----------------------+----------+-------------+----------------------+------------------+-------+
| NAME  | STATUS  | PAYMENT | COUNTRY | ONLINE | LAST ONLINE          | TOTAL    | LIMIT       | TRAFFIC UPDATED      | ACCESS UNTIL     | CREDS |
+-------+---------+---------+---------+--------+----------------------+----------+-------------+----------------------+------------------+-------+
| alice | enabled | paid    | Германия | online | 2026-06-23 12:31 UTC | 12.00GB  | без лимита  | 2026-06-23 12:31 UTC | 2026-07-23 00:00 | 2/2   |
+-------+---------+---------+---------+--------+----------------------+----------+-------------+----------------------+------------------+-------+

Credentials
+--------+----------+-----------+-----------+-------------+---------+--------+---------+----------------------+----------------------+
| CLIENT | PROTOCOL | SECURITY  | TRANSPORT | CONNECTION  | STATUS  | ONLINE | TRAFFIC | TRAFFIC UPDATED      | LAST ONLINE          |
+--------+----------+-----------+-----------+-------------+---------+--------+---------+----------------------+----------------------+
| alice  | vless    | reality   | tcp       | vless-main  | enabled | online | 8.00GB  | 2026-06-23 12:31 UTC | 2026-06-23 12:31 UTC |
| alice  | trojan   | tls/caddy | ws        | trojan-main | enabled | online | 4.00GB  | 2026-06-23 12:28 UTC | 2026-06-23 12:28 UTC |
+--------+----------+-----------+-----------+-------------+---------+--------+---------+----------------------+----------------------+
```

`IN` - трафик от клиента к серверу, `OUT` - трафик от сервера к клиенту.
`PAYMENT` показывает `free` или `paid`. Только `paid` участвует в расчёте оплаты и получает напоминания об оплате.
`COUNTRY` показывает страну выбранного каскада. Если у клиента нет действующего выбора и каскад активен, список показывает страну активного каскада. Недостающие данные для отображения вычисляются в памяти и не сохраняются в базу при просмотре списка.
Значения показываются в удобных единицах: `KB`, `MB` или `GB`.
`ONLINE` показывает `online`, если за последние 5 минут было зафиксировано принятое подключение или прирост трафика.
`TRAFFIC UPDATED` - последнее время, когда у клиента изменился `IN` или `OUT`.
`LAST ONLINE` - последнее время, когда Xray зафиксировал подключение клиента к серверу.
`ACCESS UNTIL` показывает дату и время отключения в часовом поясе менеджера или зелёную надпись `бессрочно`, если срок не установлен.
`LIMIT` показывает `без лимита`, дневной лимит `/day` или месячный лимит `/month`.

Накопительная статистика сохраняется в `/usr/local/etc/xray/manager.db` и переживает перезапуск Xray или сервера.
`xray-traffic-sync.timer` сохраняет счётчики раз в минуту, а `xray.service` пытается сохранить их перед штатной остановкой.
История по часам и дням хранится 6 месяцев, после этого старые дневные bucket удаляются автоматически.
Общий суммарный трафик клиента (`IN`, `OUT`, `TOTAL` в `xray-client list`) хранится постоянно.
Отчёты используют часовой пояс менеджера.
После смены часового пояса новые почасовые и дневные bucket статистики будут записываться уже по новой зоне.
Статистика начинает считаться после включения Xray stats и не восстанавливает трафик, который прошёл раньше.

## Восстановление записей клиентов

Если схема SQLite новее поддерживаемой менеджером, `enable`, `set-days` и `extend-days` сообщают об ошибке совместимости. Для работы с этой базой используй версию менеджера, которая поддерживает её схему.

Если версия схемы совместима и клиент присутствует в управляемом подключении `config.json`, но отсутствует в SQLite, операции `enable`, `disable` и `set-days` завершаются ошибкой `Client exists only in config.json` с предложением сначала выполнить восстановление. Для восстановления отсутствующих записей клиентов и credentials запусти

```bash
xray-client repair
```

Команда показывает имена клиентов, теги подключений и протоколы без UUID и паролей. Credential, который будет восстановлен отключённым, помечен `[disabled]`. Подтверди восстановление ответом `y` или `yes`. Другой ответ или конец ввода отменяет операцию без записи. Подтверждение запрашивается до захвата `manager.lock`. После захвата блокировки команда заново сверяет кандидатов и при изменении списка или данных прекращает операцию. Запусти её повторно и проверь новый список.

В SQLite должны уже существовать записи соответствующих подключений. Кандидат без непустого пароля Trojan или ID VLESS, неоднозначная принадлежность клиента или credential, дублирующиеся записи и отсутствующее подключение блокируют восстановление. Устрани причину и повтори команду. Если кандидатов нет, команда сообщает об этом и ничего не записывает. При ошибке записи транзакция откатывается целиком.

Команда добавляет недостающих клиентов и credentials из активных управляемых подключений и сохраняет существующие данные. Она также может восстановить credential из прежних полей клиента. Запись выполняется только в SQLite. Для каждого credential используется существующая запись подключения.

Если основной credential сохранился в прежних полях клиента, но его отдельной строки в SQLite нет, `repair` восстановит его при совпадении протокола и ID VLESS или пароля Trojan с активной записью подключения. При добавлении другого credential или наличии отдельных credentials у клиента команда также найдёт основной credential из прежних полей, если его управляемое подключение по-прежнему есть в `config.json`. Когда в этом подключении нет активной записи клиента, credential восстанавливается отключённым и показывается с пометкой `[disabled]`. UUID клиента сохраняется. При конфликте данных команда остановится без записи.

Если прежний `repair` уже добавил другой credential и основной перестал быть доступен, после обновления менеджера повторно запусти `xray-client repair`, проверь список и подтверди восстановление. Это возможно, пока данные основного credential сохранились в прежних полях клиента. Для включения восстановленного credential используй `xray-client enable ИМЯ --connection ТЕГ`.

`xray-client link` использует credential из SQLite, если он есть. Для Trojan при отсутствии credential команда берёт пароль активного клиента из выбранного управляемого подключения в `config.json`. Вывод ссылки не восстанавливает запись в SQLite. После восстановления для изменений клиента повтори исходную команду.
